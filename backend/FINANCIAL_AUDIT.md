# Санхүү, тооцооллын аудит — 2026-10-12

Захиалгын дүн, төлбөрийн дэвтэр, QPay буцаалт, лизингийн шимтгэл,
эзэмшлийн хуваарилалт, карго/агуулах, баталгаажуулалт, борлуулалтын тайланг шалгав.
Алдаа гаргах нөхцөлүүдийг тестээр шалгаад, кодын засварыг давтан баталгаажуулав.

## Зассан асуудлууд

| Хэсэг | Алдаа гарах нөхцөл | Засвар |
| --- | --- | --- |
| Лизингийн шимтгэл | 1,500₮ × 14.1% = 211.5₮-ийг 211₮ болгож байсан | Бүхэл нэгжээр бодож 212₮ болгоно; frontend/backend ижил дүрэмтэй |
| Эзэд рүү хуваарилах | Том дүнгийн завсрын үржвэр нарийвчлал алдаж нэг эзэнд 1₮ илүү оноож байсан | Бүхэл тооны нарийн хуваалт; хуваарилсан + үлдсэн = анхны дүн |

| Дүнгийн кэш | Төлбөр бүртгэхтэй зэрэг дахин тооцоход paidAmount=100,000₮-ийг хуучин 0₮-өөр дарж байсан | Дэвтэр унших, дүн бодох, кэш бичих нэг гүйлгээтэй |
| Каргоны зэрэгцээ тооцоо | Цуцлалттай давхцахад цуцалсан мөрөөс 8,000₮ өр дахин нэмэгдэж байсан | Мөр/төлөв уншихаас эхлэн захиалгыг түгжинэ |
| Агуулахын зэрэгцээ тооцоо | Хүргэлт сонгохтой давхцахад хассан 10,000₮ хураамж буцаж нэмэгдэж байсан | Шинэ сонголтыг түгжээ дотор уншиж хураамж, үлдэгдлийг хамт шинэчилнэ |
| Өдрийн тооцооны нэгтгэл | Нийлбэр 2,147,483,647₮-өөс давахад PostgreSQL алдаа өгч байсан | Дүнгийн нэгтгэл 64-бит; 3,000,000,000₮-ийн тесттэй |

Буцаалтын дүнгийн шалгалт NaN болон бутархай төгрөгийг зөвшөөрөхгүй болсон.
Итгэлд төлөх тооцооны төлбөрийг захиалгын буцаалтын урсгалаар буцаахыг хориглоно;
ингэснээр хэрэглэгчийн дэвтэр болон байгууллагын тооцоо зөрөхөөс сэргийлнэ.

## Шалгалт

- Backend: 531 тест, 73 файл.
- Frontend: 60 тест.
- 18 шинэ тест нэмсэн: backend 16, frontend 2.
- Шимтгэлийн 0.1–100%-ийн бүх зөвшөөрөгдсөн хувь, таван үнийн утгаар
  frontend/backend тус бүр 5,000 тохиолдлыг шалгасан.
- Бодит локал PostgreSQL дээр түгжээ, зэрэгцээ буцаалт/баталгаажуулалт,
  төлбөрийн кэш, карго/агуулахын гүйлгээг шалгасан.
- Backend/frontend TypeScript болон backend build шалгалт амжилттай.
- Хуучирсан хоёр тестийг одоогийн нэвтрэх зам болон шинэчилсэн модулийн замтай тааруулсан.
- Тестийн өгөгдөл үүсгэгчийн утасны дугаар санамсаргүй давхцах асуудлыг зассан.

## Дахин ажиллуулах

Тусдаа локал PostgreSQL тестийн сан үүсгэж, одоогийн migration-уудыг байрлуулсны дараа backend хавтсаас:

```sh
ITGEL_TEST_DATABASE_URL='postgresql://TEST_USER:TEST_PASSWORD@127.0.0.1:5432/itgel_test' npm run test:isolated
npm run typecheck
npm run build
```

Frontend хавтсаас:

```sh
node --test tests/*.test.mjs
./node_modules/.bin/tsc --noEmit --incremental false
```

`test:isolated` нь зөвхөн localhost/127.0.0.1 сан зөвшөөрч, QPay/SMS/storage-г
mock/console орчинд ажиллуулна. Тестүүд бичилт хийдэг тул тусдаа тестийн сан хэрэглэнэ.

Энэ шалгалтаар production өгөгдөл болон жинхэнэ QPay гүйлгээ ашиглаагүй.
QPay үйлчилгээний хариуг дуурайлган шалгасан; жинхэнэ merchant холболт, банкны
гүйлгээтэй тулгалт, production дахь өмнөх зөрүүтэй дүнг нөхөх ажлыг хийгээгүй.
Засварууд локал кодод орсон; сайт руу deploy хийгээгүй. Схемийн шинэ migration шаардахгүй.
