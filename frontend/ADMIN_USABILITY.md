## Доторх үйлдлийн шинэчлэлт

- Захиалга үүсгэх: хэрэглэгч → бараа → шалгаж үүсгэх гэсэн гурван алхам.
  Утас дангаар хэрэглэгч үүсгэнэ; байгаа утсыг дахин хэрэглэгч үүсгэлгүй ашиглана.
  Утас, и-мэйл хоёр өөр бүртгэлд байвал нийлүүлэхгүй.
  Төлбөрийн анхдагч төлөв NEW/төлөөгүй. Хэрэглэгч QPay-ээр төлнө; захиалга үүсгэхдээ гараар бэлэн орлого бүртгэхгүй.
- Бараа сонгох: хайлтаас шууд нэмэх, нэг гаргалтын өөр сонголтыг нэмэх, +/− тоо,
  сонголт бүрийн болон нийт үлдэгдлээс хэтэрсэн тоог урьдчилж шалгах.
- Захиалгын дотор: төлбөр, бараа/олголт, түүх тусдаа. Үйлдлийн дараах шинэчлэлт
  бүтэн дэлгэцийг хаахгүй. ARRIVED-ийг олголтын ширхэг сонгох урсгалаар нээнэ.
- Олголт: утас, нэр, код, QR холбоосыг нэг талбараас Enter-ээр хайна.
  Амжилттай олгосны дараа дараагийн хэрэглэгч хайхад бэлэн байна.
- Ачаа: ирэлт, карго, бараа, захиалга, түүхийг тусад нь ажиллуулна. Дутуу мөрүүдийг
  шүүж, үлдсэн бүх тоог нэг дор бөглөнө. FIFO урьдчилсан хуваарилалтыг хэвээр батална.
- Барааны мэдээлэл: нэр, зураг, өнгө/хэмжээ, хэмжээний хүснэгтийг тусдаа ажиллуулна.
  Хадгалаад тухайн бараагаар шууд бэлэн/урьдчилсан гаргалт нээнэ.
  Олон сонголтын утга болон сонголт бүрийн үлдэгдлийг нэг дор бөглөнө.
- Үнэ, карго, үлдэгдэлд бутархай/сөрөг/буруу форматтай дүнг тэмдэг арилгаж өсгөхгүй.
  Багцын барааны ширхэгийг тухайн багцын мөрөөс харуулна.
- Хэрэглэгчийн дотор: захиалга, дутуу төлбөр, мэдээлэл засах тусдаа;
  утасдах болон тухайн хэрэглэгчид шинэ захиалга нэмэх товч.
- Хүргэлт: код/утас/нэр/хүргэлтийн хүнээр хайх, энэ сарын бүх хүргэлтийг сонгох;
  өдөр сонгох календарыг хэрэгтэй үед нээнэ. Хэвлэлт харагдаж буй шүүлтийг ашиглана.
- Буцаалт: сарын буцаалтыг нээхэд дансны жагсаалт шууд харагдана.
- Тайлан, тооцоо: CSV татах; лизингийн тооцооны боломжит мөрүүдийг бөөнөөр сонгох.
  Лизингийн борлуулалтад 50-аас цааш хуудсыг үзэж, тухайн хуудсыг CSV татна.
- Дэлгүүр/лизингийн тохиргоо: зориулалтаар бүлэглэсэн талбарууд. Дэлгүүрийн
  хадгалаагүй өөрчлөлтийг харуулж, буцааж болно; хэсэг солиход драфт үлдэнэ.
- SMS: лизингийн хэрэглэгчийн жагсаалтаас хүлээн авагч сонгоно. Давхардлыг хасах,
  буруу дугаарыг засах; урьдчилж хараад илгээх алхам хэвээр.

Эцсийн баталгаажуулалт: backend 536/536, frontend 75/75, хоёр build болон
TypeScript, өөрчилсөн файлуудын ESLint амжилттай. Browser-ээр утасны хэрэглэгчийн
төлбөргүй захиалга үүсгэх, гурван хэмжээтэй бараа хадгалаад бэлэн гаргах, үлдэгдлийг
бөөнөөр бөглөх, ирэлтийн preview, тохиргооны драфт/буцаах, олголтын Enter хайлт,
SMS хүлээн авагч сонгох, CSV таталт болон 390×844 дэлгэц шалгасан.
Эдгээр туршилт зөвхөн тусгаарласан локал өгөгдөлтэй; жинхэнэ SMS/банк/QPay ашиглаагүй.

## Лизинг ба төлбөрийн урсгалын засвар — 2026-10-12

- Админ доторх хоёр ажлын хэсгийг солих цэсийг хасав. Хадгалсан destination мэдээллээр эрх нэмэхгүй; STAFF шинэ захиалга үүсгэх дэлгэцэд орохгүй.
- Тэр үеийн дүрэм: хэрэглэгчийн төлбөр зөвхөн QPay; дансны бүртгэл зөвхөн LEASING-д байсан. 2026-10-13-нд ADMIN-only дүрмээр солигдсон. Олголт, хүргэлт мөнгө автоматаар авахгүй.
- “Итгэлд төлөх” дээр QPay товч, тайлбар шууд харагдана. QR, банкны аппын холбоос, хэсэгчилсэн төлөлт, үргэлжлүүлэх, шалгах, цуцлах үйлдлүүд хадгалагдсан.
- 50 мөрийн төлбөрийн хязгаар; бутархайг тэмдэг арилгаж өсгөхгүй; сонголт/дүн солиход хуучин preview ашиглахгүй; төлөх хүсэлт давхар явуулахгүй.
- Лизингийн өөрийн бэлэн борлуулалтыг батлах боломжтой. SMS, буцаалт, бэлэн бараанд шилжүүлэхийг дэлгэрэнгүйгээс шууд олно. Шилжүүлгийн үнэ, тоо болон ачаалах алдаа ил тод.
- Лизингийн хэрэглэгч/барааны 100-аас цааш хуудсууд харагдана. Буцаасан, цуцалсан төлөлтийн түүх, шалтгаан болон баримт харагдана.
- Гараар бүртгэсэн мөнгөний хүлээн авагчийг тэмдэглэнэ. Лизингийн буцаалтаар Itgel-д орсон каргоны мөнгийг ашиглахгүй.
- HTTP + Postgres бүтэн урсгал: хэрэглэгчийн лизингийн QPay, Itgel-д хэсэгчилсэн QPay ба дансны баталгаа, карго, хэсэгчилсэн олголт; бэлэн барааны QPay ба хүргэлт; лизингээс бэлэн борлуулалтад шилжүүлэх ба дахин борлуулах. Давтан хүсэлт, өөр эзний эрх, хоёр QPay дансыг шалгасан.
- 539 backend, 78 frontend шалгалт; TypeScript, build, өөрчилсөн frontend файлуудын ESLint шалгалт.
- Одоогийн сангийн уншилт: захиалгын дэвтэр/кэш, Itgel-ийн snapshot/хуваарилалт, бэлэн барааны үлдэгдэлд зөрүү илрээгүй.
- Энэ удаагийн дотоод сайт руу browser нэвтрэхийг зөвшөөрлийн бодлого хориглосон; browser-ийн харагдах байдал/товшилтыг баталсан гэж үзэхгүй.
- Үндсэн API дээр бодит QPay: хэрэглэгч → Itgel, хэрэглэгч → лизинг, лизингийн админ → Itgel гурван нэхэмжлэл тус бүр үүсгэж, төлөгдөөгүйг шалгаад цуцлав. Нэхэмжлэл бүр QR болон 23 банкны аппын холбоостой байсан. Жинхэнэ төлбөр 0; туршилтын бүртгэлүүдийг цэвэрлэж, QA захиалга/админ/төлбөр 0 үлдсэнийг шалгасан.

## Ачаалал ба SMS — 2026-10-13

- Дэлгүүрийн барааны загварын жагсаалт үнэ/нөөцийн бүх матрицыг татахгүй. Зураг, тайлбар, сонголт, хэмжээний хүснэгт болон засварлах мэдээлэл хадгалагдсан; бүтэн гаргалтуудыг дэлгэрэнгүйгээс авна.
- Бараа болон захиалгын эхний хуудас 30 мөр. Захиалгын хүснэгт ерөнхий тоон мэдээлэл, багцын жагсаалтыг хүлээхгүй; захиалгын дэлгэрэнгүй бодит төлбөрийн дэвтрээ авмагц нээгдэж, QPay мэдээлэл тусдаа ачаална.
- Нэг HTTP хүсэлтийн давхар эрхийн шалгалт нэг баталгаажуулалт ашиглана. Шинэ хүсэлт бүрт идэвх, эрх, tokenVersion-ийг дахин уншдаг; сесс хүчингүй болголтыг кэшлэхгүй.
- SMS сервер дээр 4 хүртэл илгээлт зэрэг ажиллана. Дэлгүүрийн ирэлтийн SMS хэрэглэгчийн утсыг бөөнөөр уншина. CallPro хариуны бие гацсан ч 8 секундын хязгаар үйлчилнэ; timeout-ийг хүргэгдсэн гэж үзэхгүй, автоматаар давхар явуулахгүй.
- Гурван SMS дэлгэц 8 хүлээн авагчаар хэсэгчлэн илгээж явц харуулна. Баталсан мессежийн fingerprint, илгээлтийн нэг түлхүүр хадгалагдана; хүсэлт тасарвал дараагийн хэсгийг илгээхгүй, хэдэн дугаарын хүсэлт дууссаныг тайлагнана.
- Дахин илгээсэн ижил confirmation нь цагийн лимитийг дахин зарцуулахгүй. Өөр өөр SMS-ийг 40/цагийн хязгаарт хэвээр барина.
- Хүсэлт тасрахад баталсан SMS-ийн sendKey-г дахин ашиглана. Өмнөх хэсэг хүргэгдсэн болсон ч retry хийхэд шинээр SMS явуулахгүй. Дэлгэцийн серверийн бүсийг мөн `hnd1`-д тогтоов.
- Ирсэн/олгоогүй захиалгын хуудас тогтмол дараалалтай: хуудас солиход мөр алгасахгүй.
- Тусгаарласан HTTP + PostgreSQL, SMS mock: 40 дугаар дараалсан 5033 мс → зэрэгцээ 1278 мс. Барааны хөнгөн жагсаалтын засварлах талбарууд, 16 ирэлтийн SMS-ийн хоёр хэсэг, 16 лизингийн сануулга ба replay, гацсан response body, эрх хүчингүй болголтыг шалгав. Жинхэнэ SMS илгээгээгүй.
- 549 backend, 81 frontend шалгалт; хоёр TypeScript, backend build, frontend Webpack build болон өөрчилсөн файлуудын ESLint. Локал Turbopack build орчны порт үүсгэх хязгаарлалтаар тасарсан; production дээр үндсэн Turbopack build амжилттай.
