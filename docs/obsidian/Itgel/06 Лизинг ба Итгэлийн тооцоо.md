# Лизинг ба Итгэлийн тооцоо

Лизингийн админ өөрийн захиалгыг хариуцна. Шимтгэл төлөгдөөгүй шинэ лизингийг
ердийн батлагдсан ажил гэж үзэхгүй. Төлөлт: шимтгэл → үндсэн төлбөр → үлдсэн төлбөр.
Хуваарь нь тохиргооны өдрүүдээр өнөөдрийн болон хоцорсон төлөлтийг харуулна.

Итгэлээс лизингээр борлуулсан барааны төлбөр нь `ItgelSettlement` snapshot-д
барааны мөр, тоо, үнэ, эзнийг тогтоон хадгална. Лизингийн админ Итгэлд QPay төлнө.
Сонгосон мөр, хэсэгчилсэн дүн, allocation, нэг идэвхтэй нэхэмжлэл, шалгах/үргэлжлүүлэх/цуцлахтай.

Тооцооны төлөв: OPEN, INVOICED, PENDING_BANK, PAID, VOID.
Төлөлтийн түүх: PENDING, CONFIRMED, REJECTED, SUPERSEDED гэх мэт.
Хуучин дансны хүсэлтийг үндсэн админ шалгаж шийдэх түүхийг хадгална.
Шинэ дүрмээр лизингийн админ дансны орлого бүртгэхгүй; QPay урсгал хэвээр.

Үндсэн админы “Лизингийн тооцоо”-нд зөвхөн ADMIN хариуцагч сонгож, төлөөгүй
мөрүүдээс дансаар орсон дүн, дугаар, огноо, баримтын холбоосыг хадгална.
`POST /api/admin/leasing-settlements/bank-payment` нь PENDING_BANK үүсгэнэ.
Хүлээгдэж буй хэсгээс бодит мөнгийг тулгаж ADMIN баталсны дараа үлдэгдэл буурна.
OWNER болон лизингийн порталд дансны үүсгэх/батлах эрх олгохгүй.
Нэг гүйлгээ захиалгын дэвтэр болон Итгэлийн тооцоонд давхар орохгүй;
QPay-ийн нэхэмжлэлийн дугаарыг дансны дугаар болгон ашиглахгүй.

Өрийг бэлэн бараанд шилжүүлэх/хаах нь мөнгө авсантай адил биш. Хуучин холимог
эзэмшлийн захиалгын хуваарилалт, батлагдсан орлого, хуваарилаагүй дүнг салгаж харуулна.

Код: `lib/leasing.ts`, `lib/leasingAccess.ts`, `services/itgelSettlement*.ts`, `services/leasingReady*.ts`.
