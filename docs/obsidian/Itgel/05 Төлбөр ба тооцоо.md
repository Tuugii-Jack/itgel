# Төлбөр ба тооцоо

## Мөнгөний үндсэн дүрэм

Төлбөрийн `Payment` дэвтэр нь эх сурвалж. PAYMENT дүн эерэг орлого,
REFUND дүн эерэг хадгалагдана, нийлбэрт хасагдана. Кэш дүнг дэвтрээс дахин бодно.
Бичилтийг устгаж түүхийг өөрчлөхгүй; буцаалт/залруулгаар тайлбарлана.

Нийт = идэвхтэй барааны дүн + карго + агуулах + лизингийн шимтгэл.
Хүргэлтийн компаний авах төлбөр дэлгүүрийн нийт дүнд орохгүй.
Үлдэгдэл = нийт − цэвэр төлсөн дүн − хаасан өр.
Өр хаасан дүн нь мөнгө орсон гэсэн үг биш. Буцаалт хүлээн авагчийн цэвэр орлогоос хэтрэхгүй.

## Хүлээн авагч

| Орлого | Хүлээн авагч |
|---|---|
| Итгэлийн энгийн бараа | SHOP |
| Лизингийн шимтгэл/үндсэн төлбөр, өөрийн бэлэн борлуулалт | LEASING |
| Карго/агуулах | SHOP |

Хоёр QPay merchant-ийн төлбөрийг хооронд нь сольж болохгүй.
Нэг төлбөрийг QPay callback/verify давтаж дэвтэрт нэмэхгүй.

## Дансны бүртгэл — 2026-10-13-ны шинэ заавар

Зөвхөн ADMIN бүртгэнэ. LEASING, STAFF, CUSTOMER, OWNER-д хориглоно.
QPay-г гараар төлсөн мэт бичихгүй. Дансанд орсон бодит мөнгийг шалгаад захиалга,
хүлээн авагч, дүн, гүйлгээний дугаарыг тэмдэглэнэ. Давхар болон зөрүүтэй бичилтээс
сервер дээр хамгаална. Гараар орлого нэмэх үед сан/дэвтрийн transaction ба lock хэрэглэнэ.

- `POST /api/admin/orders/:id/payments`: зөвхөн BANK_TRANSFER, эерэг бүхэл төгрөг.
- Гүйлгээний дугаар заавал, ихдээ 120 тэмдэгт; зайг цэвэрлэж том үсгээр хадгална.
- Ижил захиалга/хүлээн авагч/дүн/дугаар дахин ирвэл өмнөх бичилтийг буцаана.
- Өөр захиалга, өөр дүн, өөр хүлээн авагчид ижил дугаар ашиглахгүй.
- QPay-ийн өмнөх дугаар, Итгэлийн тооцооны дугаарыг дансны орлого гэж давхар нэмэхгүй.
- Хүлээн авагчийн бодит үлдэгдлээс хэтрэхгүй; лизинг болон SHOP дүнг тусад нь шалгана.
- Устсан, цуцалсан, өр хаасан захиалгад шинэ орлого нэмэхгүй.
- Нэг дугаарын advisory lock болон захиалгын lock нь зэрэг хүсэлтийн давхардлаас хамгаална.
- Шимтгэл бүрэн орсон лизингийн захиалга өмнөх баталгаажуулалтын урсгалаар ажиллана.
